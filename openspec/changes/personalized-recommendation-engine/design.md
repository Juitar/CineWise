## Context

现有推荐实现只查询单个 `movieId + cinemaId` 的 A 场次，并在没有场次时返回不可购内容候选；它没有城市召回、类型/评分排序或记录。真实内容同步已提供影片类型和评分，A 的 `ShowQueryService` 仍是场次、票价和可售判断的唯一公开来源。

## Goals / Non-Goals

**Goals:**

- 在 D 模块内实现可复现、可解释的候选过滤、评分、去重、降级和记录。
- 用最小画像摘要提升排序，同时保证当前需求与关闭开关的优先级。
- 清楚区分真实内容资料、Demo 内容和 A 的可购场次，保证每个动态字段可追溯。

**Non-Goals:**

- 不把 NetStart 或其他内容 Provider 当作票务 Provider，不接入真实票价、库存、座位、订单或支付。
- 不实现 B 的 Agent 运行、工具路由、SSE、确认、`PLAN_CARD` 发送；不实现 C 的页面。
- 本期不新建推荐表、迁移或历史记录 REST。

## Decisions

### 1. 先以 A 的公开批量候选查询作为实现前置条件

当前 `ShowQueryService` 只能按单个影片、单个影院查询，不能支持“按城市、日期、预算等条件召回多候选”。D 不得访问 `movie_show`、Mapper 或 Controller 规避这个限制。方案先由 A 确认一个只读批量候选 Application API：必须明确输入范围、返回场次字段、来源、过期、空结果和异常语义；D 仅在适配器中映射，不复制票务数据。

替代方案是由 D 读取票务表或由真实内容补全场次，但两者都会让非票务模块伪造或越权读取交易事实，不能采用。

### 2. 直接复用内容类型和评分，不新增影片标签

推荐直接读取 `MovieContent.genresJson` 和 `rating`，不新增 `movie_tag`，也不为类型和评分复制一份表数据。用户本轮指定的类型或排除类型在评分前过滤；内容评分只参与排序。情绪、场景、恐怖、烧脑、节奏和 AI 判断本次全部不做，避免在数天开发周期内引入人工标注、数据质量和维护负担。

### 3. 使用固定评分与明确的并列顺序

`rec-mvp-1` 先执行硬过滤，再计算价格、时间和评分；综合/低价/时间三类权重、并列顺序和 `showId` 去重采用本 change 固定规则。缺失评分项从分母移除并返回 `missingFactors`。

替代方案是交给模型决定排序，但无法稳定复现，也可能把不存在的票务事实写进卡片，不能采用。

### 4. 工具结果和卡片字段由同一规格控制

`RankMoviePlanTool` 返回 `RecommendationPlanResult`；B 将其作为 `PLAN_CARD` 载荷发送，C 只展示已提供字段。D 不发送 SSE，B 不改写价格、场次、分数、有效期或证据，C 不补造缺失可购信息。`runId` 只来自 B 的受信任 `ToolContext`，用于记录去重，不作为 Command 字段。

### 5. 直线距离只用于本次附近影院推荐

用户主动选择“按距离推荐”后，C 在浏览器取得本次经纬度并直接交给 D 的距离上下文接口；B 的工具参数和模型输入不接收精确位置。D 只用 Haversine 公式计算用户位置到 `CinemaContent.longitude/latitude` 的直线距离，先取最近 10 家再查询 A 的可售场次。用户给出 `maxDistanceMeters` 时超过上限的影院先过滤；未给上限但要求距离排序时生成 `NEAREST` 方案。位置上传成功返回 HTTP 200 的统一 `Result<null>`，以兼容 C 的公共 `apiRequest<T>()`；不得返回空响应 204。结果明确展示“直线距离约 X km”，不得描述为路线距离或预计耗时。经纬度只在请求内存中使用，不写 MySQL、Redis、日志、快照、Agent 轨迹或推荐结果。

## Risks / Trade-offs

- [A 尚未提供批量候选 API] → 先完成 D 内部评分和测试夹具；公开 API 字段确认后再接入实际召回。
- [B 的工具输入和卡片 Schema 变化] → 先在 OpenSpec 写出 D 所需字段，由 B、D 确认后再改公共类型和消费者夹具。
- [真实内容与本地票务内容 ID 不一致] → 仅将有 A 可售场次引用的内容变成可购方案；其余真实内容只作为非购票内容候选或被排除，不做 ID 猜测。
- [内容评分缺失] → 仍保留符合类型、票价和时间的候选，从综合评分分母移除评分项，并返回 `missingFactors=RATING`；不伪造评分。
- [定位拒绝、影院无坐标或距离计算失败] → 省略距离过滤和 `NEAREST` 方案，继续普通城市推荐；不把它伪装成“附近没有影院”。

## Migration Plan

1. 先取得 A 的批量候选 API；B、C 确认工具和卡片字段。
2. 发布 D 的领域类型、类型过滤器、价格/时间/评分评分器和固定夹具。
3. 接入 A 的公开候选 API并完成固定夹具验证。
4. B 完成新工具登记、状态机和卡片适配，C 完成记录与卡片展示后切换 `rankMoviePlan`；异常时回退为不可购候选或固定推荐，不返回虚构可购卡。
