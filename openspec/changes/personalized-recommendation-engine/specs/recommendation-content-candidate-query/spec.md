## Purpose

让 D 在调用 A 的批量可售场次查询前，按城市从内容模块取得可追溯的影院候选和影片基础资料，不读取内容持久化实现，也不把内容资料当成票务事实。

## ADDED Requirements

### Requirement: 推荐必须通过内容公开应用 API 解析城市影院候选

系统 SHALL 提供内容模块公开的只读应用 API，按 `cityCode` 返回可用于推荐的影院业务 ID、名称、来源、数据时间、有效期和过期标识。推荐只能使用未过期或明确标为历史参考的内容候选；内容查询不可用必须返回稳定错误，不得伪装为空影院列表。

#### Scenario: 城市存在有效影院内容
- **WHEN** 推荐以合法城市编码请求影院候选
- **THEN** 系统返回该城市可追溯的影院 ID 与展示摘要
- **AND** 推荐把这些 ID 作为 A 批量可售场次查询的输入，不读取内容 Mapper、Repository 或 Controller

#### Scenario: 内容查询不可用
- **WHEN** 内容缓存、快照和 Demo 均无法提供城市影院候选
- **THEN** 系统返回内容不可用错误
- **AND** 推荐不把该错误当作“没有可售场次”
