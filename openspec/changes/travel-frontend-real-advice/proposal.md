# 真实观影提醒与出行页面

## Why

首页仍将写死的路线、距离和餐饮数据作为可操作入口，已购票用户却无法查看 D 已生成的真实出行任务和建议。D 的正式 REST 已提供任务、建议、刷新和提醒时间更新能力，需要由 C 建立独立页面并移除会误导用户的静态数据。

## What Changes

- 新增受登录保护的 `/travel/:taskId` 出行建议页，并支持订单详情按订单 ID 查询对应任务后进入。
- 新增 `modules/travel`，集中管理 DTO 校验、任务与建议查询、建议刷新、提醒时间更新和结果未知恢复。
- 页面只展示 D 返回的任务、影院、天气、通用交通建议、提醒时间、来源和有效期。
- 移除首页 `PlanRecommendation` 的静态路线、距离和餐饮入口。

## Non-Goals

- 不修改 D 的后端接口、任务状态、数据库或提醒渠道。
- 不实现浏览器定位、地图、路线规划、餐饮查询或按距离重规划。
- 不修改 Agent 卡片类型、确认动作、SSE 或其他 A/B/D 业务模块。
- 不提供关闭或重新开启提醒的开关。

## Impact

- Owner：C；D 提供并维护 `/api/v1/travel/tasks/**` DTO 和错误码，A 的订单详情只提供 `orderId` 入口。
- 前端新增 `modules/travel`、出行页面和路由，调整订单详情及首页。
- 不新增依赖，不修改后端和数据库。

## Acceptance Results

- 本人可从已支付订单进入真实出行任务，查看任务、天气、建议、来源和有效期。
- 提醒更新同时携带 `If-Match` 和请求体版本，重复点击被阻止，结果未知时只查询原任务。
- 建议刷新不自动重试，并正确展示 404、409、429、503 和降级结果。
- 首页不再展示写死的杭州影院、路线、距离或餐饮推荐。
- 桌面和移动端相关测试、生产构建及 OpenSpec 严格校验通过。
