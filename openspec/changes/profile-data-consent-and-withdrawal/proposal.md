# 画像数据同意与撤回可靠通知

## Why

D 的画像生产写入缺少 C 提供的独立同意查询，现有 boolean 接口也无法表达同意版本和撤回状态；撤回通知没有持久化投递与恢复能力。

## What Changes

- C 提供返回同意快照的 `ProfileDataConsentQuery`，并同步 D 的调用方、fallback 和测试夹具。
- C 管理独立于注册隐私政策同意、登录状态和个性化开关的画像数据保存同意记录。
- 撤回在一个 MySQL 事务内完成同意记录 CAS 更新和唯一 outbox 写入，提交后立即尝试投递并支持自动重试和人工恢复。
- 个人中心通过 `modules/profile` 调用 D 的画像标签和个性化 REST，并在 `202004` 时清除页面画像数据。

## Non-Goals

- 不修改 V017 或其他数据库迁移，不执行共享数据库迁移。
- 不修改 D 的画像清理规则、Redis 实现、推荐算法、Agent 确认或出行功能。
- 不新增查询画像同意状态的 REST。

## Impact

- C：新增同意写接口、同意持久化适配、outbox 投递和个人中心接入。
- D：使用新快照查询签名和带记录版本的撤回事件；按 eventId 去重。
- A：V017 已是本实现的数据库前置条件，本 change 不改迁移。

## Acceptance Results

- 无记录、已同意和已撤回返回唯一确定的快照字段语义。
- 撤回和 outbox 任一步失败时整体回滚；重复撤回不产生新事件。
- 自动投递失败按既定间隔重试，十次失败后只能用原 eventId 人工恢复。
- 页面收到 `202004` 后不再显示旧标签和旧开关状态。
