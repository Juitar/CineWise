# 设计

## 状态来源

不新增同意状态查询 REST。`useProfile` 继续读取 `/api/v1/profile/me/tags`：读取成功表示画像数据使用已开启；返回 `202004` 表示未开启；加载中或其他错误表示状态未知，页面禁用开关并展示现有错误提示。

开启请求使用当前 `/auth/me` 返回的 `privacyPolicyVersion` 调用 `PUT /api/v1/auth/profile-data-consent`。这个版本只作为本次独立同意的政策版本记录，动作本身仍与注册同意分开。关闭调用 `DELETE /api/v1/auth/profile-data-consent`。

## 前端分层

`modules/profile/api.ts` 提供开启和撤回函数；`useProfile` 管理画像数据、同意状态和两个开关的提交状态；`pages/profile` 只传入当前隐私政策版本并渲染开关，不直接请求接口。

## 写操作与恢复

开启成功后调用现有只读画像 REST 获取最新页面数据。关闭成功后立即进入 `consent-required`，清除标签和个性化结果。

同意或撤回遇到 409、网络中断、超时或响应格式异常时，不重发写请求，只调用一次现有画像 REST 判断最新状态。明确的 401、422 和 5xx 显示对应提示；无法读取最新状态时保持 `error`，开关禁用，避免把未知状态当作关闭。

画像同意写操作与个性化写操作不能并发，任一提交中都禁用两个开关。组件卸载仍取消读取请求并清除页面内存画像。

## 页面与移动端

画像卡片顶部展示“使用用户画像”开关和用途说明。开启后才展示“开启个性化”开关及标签；关闭后保留 `未开启画像数据使用` 提示。移动端保持单列，开关触控区域不小于 44px。

## 测试

- API 测试校验同意和撤回路径、方法及政策版本请求体。
- Hook 测试覆盖初始开启/关闭、开启成功、关闭清理、重复提交拦截、409 和结果未知后的只读恢复、401/422/5xx。
- 页面测试覆盖两个开关的区分、未同意时可开启、提交禁用、关闭后不显示旧画像和移动端可用结构。
