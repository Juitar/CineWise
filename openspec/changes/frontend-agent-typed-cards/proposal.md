# Agent 类型化卡片前端展示

## 背景与目标
Agent 工作区已经能把后端卡片事件投影为安全文本，但目前所有类型共用一段通用 `<article><dl>`。本变更由 C 将现有正式 payload 拆成可复用、可测试、适配桌面和移动端的类型化卡片组件。

## 范围
- 为 `TEXT`、`QUESTION`、`MOVIE_CARD`、`PLAN_CARD`、`BUSINESS_INTENT`、`PROGRESS`、`ERROR` 提供明确的前端展示组件。
- 由统一注册表按 `AgentDisplayItem.kind` 选择组件，未知类型保留固定安全占位。
- 在安全投影中补充问题选项等展示所需的白名单字段，不把原始 payload 传给组件。
- 保留确认卡现有确认、拒绝、禁用和结果恢复行为。
- 补组件单测、投影测试和桌面/移动浏览器测试。

## 非范围
- 不新增 `TRAVEL_ADVICE_CARD`、`ROUTE_CARD`、`ORDER_CONFIRM`、`REFUND_CONFIRM` 或后端未提供的 DTO。
- 不新增问题回答、方案选择或其他写接口，不修改后端、数据库、SSE 和认证协议。
- 不修改个人中心、内容同步、天气、路线、餐饮、订单或退票页面。

## Owner 与影响
C 负责前端实现。B 的卡片 DTO、确认接口和历史消息 `runId` 保持不变；A、B、D 无需为本变更新增接口。

## 验收结果
- 七类正式 payload 有各自清晰的安全展示，危险文本按 React 文本规则转义。
- 卡片只消费安全投影，不显示工具参数、任意 URL、actionId 或未声明字段。
- 桌面和移动端共用同一套组件，信息不溢出且操作可用。
- 确认卡按钮及原有恢复规则无回归。
