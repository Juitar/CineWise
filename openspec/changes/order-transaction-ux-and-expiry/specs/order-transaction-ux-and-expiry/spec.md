# 需求：订单交易页面与过期释放修复

## ADDED Requirements

### Requirement: 场次时间显示

系统 MUST 使用统一订单时间格式化规则，将退款摘要和替代场次的带时区 ISO 8601 时间展示为中国业务时区的 `YYYY-MM-DD HH:mm`。

#### Scenario: 退款和替代场次显示中国业务时间

- **当** 服务端返回带时区的 ISO 8601 场次时间
- **则** 退款摘要和替代场次展示 `YYYY-MM-DD HH:mm`
- **并且** 使用统一订单时间格式化规则，不在组件内手工截断字符串。

### Requirement: 日期筛选

系统 MUST 使用 Ant Design `DatePicker` 承载个人订单日期筛选，并以 `YYYY-MM-DD` 字符串将选择结果交给订单查询模块。

#### Scenario: 个人订单日期筛选初始为空

- **当** 用户首次打开订单列表
- **则** 使用 Ant Design `DatePicker` 且没有预填日期
- **当** 用户选择日期或清除日期
- **则** 页面以 `YYYY-MM-DD` 重新查询服务端订单列表。

### Requirement: 场次日期区分

场次列表 MUST 展示服务端场次开始时间对应的中国业务日期，不能只展示时分。

#### Scenario: 跨日期相同时间的场次可区分

- **当** 服务端返回两个日期不同但开场时分相同的场次
- **则** 每个场次卡片展示 `YYYY-MM-DD` 日期和 `HH:mm` 开场时间
- **并且** 日期使用统一业务时区格式化，不在页面中手工解析时间字符串。

### Requirement: 安全返回

订单交易页面 MUST 提供不回到旧建单确认地址的安全业务返回入口，且返回动作 MUST NOT 自动发起任何交易写请求。

#### Scenario: 写页面和终态页面返回

- **当** 用户在订单详情、支付、支付结果或退款页点击返回
- **则** 跳转到当前业务流程的安全目标，不回到旧的订单确认建单 URL
- **并且** 不自动重新提交支付、取消或退款请求。

### Requirement: 替代场次影院边界

替代场次查询 MUST 在数据库侧限定原订单的 `cinemaId`，不得把其他影院的同影片场次返回为同影院候选。

#### Scenario: 查询同影院替代场次

- **当** 用户查询一笔订单的替代场次
- **则** 只返回同一 `movieId`、同一原 `cinemaId`、排除原 `showId`、仍在售且有可用座位的场次
- **并且** 不读取内容模块的 Entity、Mapper 或 Repository。

### Requirement: 过期释放

订单过期调度 MUST 使用订单权威状态和座位归属，将到期的待支付订单迁移为 `EXPIRED` 并只释放其仍锁定的座位。

#### Scenario: 待支付订单到期

- **当** 受控调度窗口扫描 `expire_time <= businessNow` 的 `PENDING_PAYMENT` 订单
- **则** 订单迁移为 `EXPIRED`，并只释放该订单仍锁定的座位
- **并且** 已支付、已取消或已被其他流程取得权威结果的订单不被回退或重复释放。

### Requirement: 不可退订单提示

系统 MUST 在退款影响查询返回 `205006 ORDER_NOT_REFUNDABLE` 时展示明确不可退状态，不得使用金额为零的退款摘要或可提交的退款表单替代该业务结果。

#### Scenario: 已开场订单请求退票

- **当** 已支付订单关联的场次已开场，退款影响查询返回 `205006`
- **则** 页面展示服务端不可退消息和返回订单详情入口
- **并且** 不展示退款金额、二次确认勾选框或退票写操作按钮。
