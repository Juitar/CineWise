## Design

### 复用边界

C 现有页面使用语义化 `<nav aria-label="面包屑">`、`umi` 的 `Link` 和斜杠文本分隔符。A 在自己的 `features/transaction-breadcrumb` 中复用此 DOM 与视觉模式，不抽取或修改 C 的公共组件。

### 路径规则

- 可点击项必须是业务层级的稳定路径，且携带继续查询所需的字符串 ID。
- 当前页面只显示文本，不是链接。
- 选座到场次使用 `/shows?movieId={movieId}&cinemaId={cinemaId}`；确认订单到选座使用已有 `showId/movieId/cinemaId` 和重复 seatId 路由参数。
- 订单、支付、退款和电子票到订单详情统一使用 `/orders/{orderNo}`；电子票无法取得 `orderNo` 时只显示“我的订单”链接。
- 任何链接只导航，不重新提交建单、支付、取消或退款。

### 内容资料提示

订单的金额、场次、座位、电子票与状态是 A 的权威交易事实。影片、影院展示资料失败时，仅提示“影片或影院资料暂不可用，订单信息不受影响”并提供一次只读重试；不把每条内容资料的来源、过期或降级 Tag 堆叠到交易页面。

### 验证

- 组件单测覆盖当前项不可点击、上级链接和 `aria-label`。
- 页面测试覆盖选座、订单、支付、电子票和退票的规范链接；内容不可用时保留重试，只有来源标签时不渲染交易提示。
- 执行 `pnpm check`、OpenSpec strict 和 `git diff --check`。
