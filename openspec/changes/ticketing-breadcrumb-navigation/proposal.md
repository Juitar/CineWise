## Why

A 负责的选座、订单、支付、电子票和退票页面仍混用旧的“返回”按钮；它们与 C 已在影院和场次页面采用的语义化面包屑样式不一致，且深链或刷新时不应依赖浏览器历史决定返回目标。订单页同时把每条内容资料的来源与时效标签集中堆叠，干扰交易信息阅读。

## What Changes

- A 的交易页面复用 C 的原生语义化面包屑模式：`nav + Link + / + current`，不修改 C 的公共布局、路由或组件。
- 面包屑链接只指向带完整业务 ID 的规范页面；不使用 `history.back()`，不触发任何写操作。
- 场次页的影院层级链接到对应影院详情；选座、确认订单、订单详情、支付、电子票和退票展示对应业务层级。
- 订单页面仅在内容不可用时展示紧凑降级说明与重试入口；不重复展示每条影片、影院资料的来源/时效标签。内容资料的来源提示仍保留在 C/D 负责的影片、影院浏览页面。

## Non-Goals

- 不修改 `.umirc.ts`、公共布局、认证、请求层、C 的影片/影院页面或 D 的内容 DTO。
- 不变更订单、支付、退票、电子票接口、状态机或 URL 契约。

## Owners

- A：交易页面导航和订单内容降级展示。
- C：既有页面级面包屑范例、公共路由与布局保持不变。
- D：内容来源、时效和降级事实的字段语义保持不变。
