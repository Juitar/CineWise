## ADDED Requirements

### Requirement: 用户可以使用手动地点作为一次性路线起点

系统 MUST 在用户主动选择手动地点、确认向高德共享该地点并提交有效文本后，使用该地点规划本人出行任务路线；该流程不得申请浏览器定位权限。

#### Scenario: 手动地点唯一解析并返回路线摘要

- **WHEN** 已登录用户为本人有效任务提交已确认的唯一地址或 POI 地点文本
- **THEN** 系统仅在本次请求中解析地点并调用路线 Provider，返回不含坐标、地点文本或路线折线的路线摘要

#### Scenario: 当前定位不可用后改用手动地点

- **WHEN** 浏览器定位因 HTTP、安全上下文、拒绝、不支持或超时不可用
- **THEN** 页面明确当前定位不可用并允许用户切换到手动地点，不自动重试定位

### Requirement: 手动地点不得静默降级或选择

系统 MUST 拒绝空、无法唯一解析、城市或区县粒度的手动地点，且不得从多个候选中自动选择任何一个。

#### Scenario: 地点存在多个候选

- **WHEN** 地理编码返回多个候选
- **THEN** 系统返回稳定的地点歧义错误，页面要求用户补充更完整地点，不展示候选坐标

#### Scenario: 地点粒度不足

- **WHEN** 地理编码结果仅为城市或区县
- **THEN** 系统拒绝路线规划并提示用户输入具体 POI 或地址，不调用路线 Provider

### Requirement: 手动地点保持最小化与一次性使用

系统 MUST 不把手动地点文本、其坐标或 Provider 原始候选写入数据库、Redis、日志、URL、前端存储、任务快照、Agent、SSE 或路线响应。

#### Scenario: 规划完成或失败

- **WHEN** 手动地点路线请求成功、失败、超时或被取消
- **THEN** 页面与服务端不保留该地点或坐标，后续请求必须由用户重新提供
