# 出行详情页当前位置路线

## 背景

D 的 PR #191 新增本人出行任务路线接口，浏览器可以在用户主动确认后提交一次性经纬度，获取不含坐标和路线折线的驾车或步行摘要。当前 `/travel/:taskId` 只展示任务、天气、建议和提醒，没有定位及路线入口。

## 范围

- C 在出行详情页增加驾车、步行选择和“规划路线”操作。
- 用户明确同意本次位置共享并点击后，才调用浏览器单次定位。
- 通过 `POST /api/v1/travel/tasks/{taskId}/route` 提交浏览器原始数值坐标。
- 展示 D 返回的耗时、预计出发时间、来源、数据时间和有效期。
- 同步请求类型、运行时响应校验、Mock、错误展示、桌面和移动测试。

## 非范围

- 不实现 `TRANSIT`、手动地点、地图、路线折线、持续定位、餐饮或浏览器通知。
- 不修改 D 的后端业务、Agent 消息、SSE、画像或推荐模块。
- 不保存坐标、共享确认或路线历史，不复用 `distanceContextId`。

## 负责人和协作

- C：前端 OpenSpec、DTO、API、Hook、页面、Mock 和测试。
- D：PR #191 的 OpenAPI、Controller、任务归属、影院坐标、路线 Provider 和后端测试。

## 验收结果

- 页面只在用户确认并点击后申请一次浏览器定位，重复点击在定位或请求期间被禁止。
- 请求只含 `longitude`、`latitude`、`travelMode` 和 `thirdPartySharingConfirmed=true`。
- 定位拒绝或失败、坐标非法、影院无坐标和路线服务失败统一显示“路线暂不可用”，且不自动重发 POST。
- 精确坐标不进入 React state、URL、存储、日志、埋点、Mock 快照、Agent 或 SSE，页面卸载后没有坐标残留。
- 任务失效或建议过期时路线操作只读；桌面和移动端均可操作。
