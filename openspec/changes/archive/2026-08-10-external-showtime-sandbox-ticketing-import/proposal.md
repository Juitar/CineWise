# 外部排期本地沙箱导入

## 背景

NetStart 能提供已映射的影片、影院和开场参考，但没有可靠散场时间、稳定影厅 ID、座位或余座。A 不能把这些资料直接当作真实票务库存，却可以在来源和展示语义清晰的前提下，创建本地沙箱场次供选座、建单和支付闭环演示。

## 目标

在 A 的票务边界中，将 D 公开的“可作本地沙箱参考”的外部候选幂等导入为本地影厅、场次和座位；交易金额、库存、锁座和订单始终由 A 本地数据决定。

## 范围

- 只经 D 的公开 Application Port 读取候选，不访问 D 的 Provider、表或持久化代码。
- 为外部三元场次身份建立 A 本地幂等映射，并以最小事务创建本地沙箱影厅、场次和座位。
- 使用 A 配置的本地票价、座位布局和预计结束时间规则。
- 保持现有场次查询、锁座、订单、支付、电子票和退票仅使用 A 本地事实。
- 覆盖重复导入、候选过期、降级、截断、状态变化和已产生交易后的安全拒绝场景。

## 非范围

- 不把外部 `listedPrice`、影厅文本、影片时长、座位或余座声明为真实交易事实。
- 不修改 D 的 NetStart 请求、限流、快照、身份映射或内容表。
- 不创建真实影院库存、真实影厅或实时外部座位同步。
- 不在 D 补齐公开 DTO 前从 `rejectedSnapshots` 中取数或依据 `END_TIME_REJECTED` 建单。

## Owner 与前置条件

- A：本地沙箱导入、影厅/场次/座位、价格、幂等映射、Flyway、票务验证。
- D：修复 `code=0` 成功响应解析，并在公开 DTO/OpenSpec 中提供已拿到的 `durationMinutes`、`auditoriumText` 和“本地沙箱参考可用”状态。
- 当前状态：D 的 DTO 契约已由 PR #152 合入；A 的 V019、导入 Application API、单元和 MySQL 8.4
  幂等验证已完成。管理员触发改为创建可查询的异步任务，避免长时间导入被 HTTP 超时误报为失败；前端展示联调仍待完成。

## 验收结果

1. 合格的外部参考候选最多生成一份对应本地沙箱场次，重复导入不重复创建影厅、场次或座位。
2. 页面和接口能区分外部开场参考与 A 本地预计结束时间、影厅、价格和库存。
3. 外部候选过期、降级、截断、身份不完整或不具备本地沙箱参考资格时，A 零写入票务表。
4. 已锁座、已售或存在订单的本地沙箱场次不被外部刷新改写。
5. 只有 ADMIN 可以按日期和最多 100 家影院创建手动导入任务；系统不自动创建新的导入任务。
