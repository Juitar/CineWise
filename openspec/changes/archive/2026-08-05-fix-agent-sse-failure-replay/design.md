## Context

`AgentMessageSubmissionService` 在最小只读工具抛出运行时异常后，会由独立短事务写入安全失败消息和终态事件，再重新抛出异常。当前 `AgentController` 只在异步任务正常返回时调用 `writeEvents`，所以浏览器当前连接收不到已保存的失败结果。该问题由 PR #53 评审指出，范围只涉及 B 的 Agent Controller、运行时应用服务和测试。

## Goals / Non-Goals

**Goals:**

- 工具异常后，在同一 SSE 连接重放已经持久化的 `message.error`、`run.complete` 等安全事件并正常结束。
- 不发送异常文本、堆栈或工具原始参数，不重复执行工具或创建运行。
- 用 Controller 测试固定该行为。

**Non-Goals:**

- 不修改 POST SSE 路径、请求/响应字段、认证、错误码、数据库迁移、事件表或事件类型。
- 不实现确认动作、写工具、自动重试、重规划或 C 前端代码。

## Decisions

### 用内部已持久化失败标记驱动异常重放

提交服务仅在 `recordFailure` 成功后抛出内部 `AgentFailurePersistedException`。Controller 的异步任务只捕获该标记，然后调用 Agent 应用服务的只读重放入口，以原 `sessionId` 和当前游标读取已提交事件，再调用现有 `writeEvents`。这样只发送已持久化的事实，不需要 Controller 了解失败事件结构或再次调用工具；参数校验、会话占用和失败持久化异常不会误触发历史事件重放。外层只保留执行器拒绝时的同步异常处理。

备选方案是让提交服务吞掉异常并返回失败快照。该方案会把 HTTP/SSE 传输要求混入持久化服务，也会掩盖独立安全失败事务本身失败的情况，因此不采用。

### 失败重放后结束 emitter，并继续使用现有载荷过滤

`writeEvents` 负责按固定事件格式发送并完成 emitter；异常分支复用它，确保没有单独的错误事件序列化路径。心跳在 emitter 完成回调中取消。异常不会写入 SSE、日志载荷或事件 JSON。

## Risks / Trade-offs

- [安全失败事务未能写入事件] → 只发送重放查询实际返回的事件，不构造或暴露异常原文；连接正常结束，客户端仍可按已有恢复规则查询运行详情。
- [读取范围错误] → 重放只使用原会话和请求游标，并且只由已完成本次用户会话校验、已持久化失败的内部标记触发，不按异常内容推断 runId。
- [异步测试不稳定] → 用 MockMvc 的异步结果等待和固定 `StreamView` 断言事件顺序、连接结束及异常文本未出现。

## Migration Plan

1. 增加失败重放的应用服务入口和 Controller 异步异常处理。
2. 新增回归测试并执行 Agent 定向测试、Maven verify 与 OpenSpec 严格校验。
3. 发布为普通后端代码修复；无需数据库迁移。若需回退，回退该修复提交即可，已保存的失败事件保持不变。
