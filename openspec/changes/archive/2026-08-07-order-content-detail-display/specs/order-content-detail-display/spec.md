# 需求：订单页面内容详情展示

## ADDED Requirements

### Requirement: 订单页面只读补充内容资料

系统 MUST 使用订单查询返回的 `movieId` 和 `cinemaId` 调用 D 已公开的详情函数，以只读方式补充影片和影院展示资料。页面不得从标题、订单号、场次号或历史路由推断内容 ID。

#### Scenario: 页面展示已取得的内容资料

- **当** 当前订单含有效 `movieId`、`cinemaId` 且详情查询成功
- **则** 订单列表、订单详情和电子票页展示影片标题、可用海报、影院名称、区域和地址
- **并且** 页面使用内容详情中的来源、来源类型、更新时间、过期和降级字段展示资料来源与时效提示
- **并且** 金额、场次时间、座位和订单状态仍只使用 A 的订单或票据接口数据

#### Scenario: 内容资料过期或降级

- **当** 影片或影院详情标记 `isExpired=true`、`degraded=true`、`sourceType=MOCK/SNAPSHOT` 或来源字段无法验证
- **则** 对应订单页面显示“数据已过期，仅供参考”“当前为降级数据”“演示数据”“历史快照”或“来源尚未验证”等提示
- **并且** 页面不得把该资料标记为实时票务、价格或库存数据

### Requirement: 内容不可用不得影响订单主链展示

系统 MUST 将内容资料查询故障与订单查询故障分离。

#### Scenario: 单项内容详情不可用

- **当** 某一影片或影院详情返回 404、网络错误或服务端错误
- **则** 对应位置显示“影片信息暂不可用”或“影院信息暂不可用”
- **并且** 页面保留订单号、订单状态、金额、场次时间、座位和允许的交易操作
- **并且** 系统不得伪造内容资料或发起交易写请求

### Requirement: 内容资料可安全重试

系统 MUST 为内容资料读取失败提供显式重试入口。

#### Scenario: 用户重试内容资料

- **当** 用户点击“重试内容信息”
- **则** 系统只重新执行当前订单引用的影片和影院 GET 查询
- **并且** 不生成新的订单、支付、取消、退款或幂等键

### Requirement: 旧内容响应不得覆盖当前订单

系统 MUST 在订单分页、路由参数或电子票关联订单变化时取消或忽略旧内容详情响应。

#### Scenario: 快速切换订单

- **当** 用户在前一批内容详情请求结束前切换订单或电子票
- **则** 前一批响应不得写入当前页面的影片或影院展示资料
