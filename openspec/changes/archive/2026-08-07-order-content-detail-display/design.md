# Design: 订单页面内容详情展示

## 数据边界

订单查询中的 `movieId/cinemaId` 是 A 的权威业务引用；D 的详情函数只补充展示资料。A 不缓存完整内容实体到持久化、本地存储或订单 DTO，也不根据标题、影院名或路由猜测 ID。

## 前端分层

`modules/order` 新增只读内容展示 Hook，集中完成：

1. 从当前订单记录提取并去重有效的 `movieId/cinemaId`；
2. 通过 D 已公开的 `getMovieDetail`、`getCinemaDetail` 并行查询；
3. 使用 `AbortController` 取消页面切换或订单分页变化后的旧请求；
4. 将每个 ID 的成功资料、不可用状态和刷新动作返回给 A 页面。

页面只组合订单查询与内容 Hook；feature 组件继续只接收展示 props，不能直接调用内容接口。页面将详情 DTO 的来源与时效字段传给只读提示组件，由 `getFreshnessNotices` 统一生成来源、过期、降级和未验证文案；不把内容资料提升为票务权威。

## 降级和重试

- 单个详情 404、网络失败或 5xx 只影响对应影片/影院展示，订单自身仍按 A 返回值渲染。
- 影片失败显示“影片信息暂不可用”，影院失败显示“影院信息暂不可用”；不伪造标题、地址或海报。
- 页面展示内容不可用提示及“重试内容信息”操作；重试只重新执行 GET，不发起建单、支付、取消或退票。
- 路由或分页变化时，仅接受当前查询批次的结果，旧响应不能覆盖新订单资料。

## 测试

- Hook：去重并行查询、单项失败降级、刷新重试、Abort 后忽略旧响应。
- 页面：订单列表、详情和电子票在资料成功/失败时的展示；断言内容失败不替换订单加载错误或交易按钮。
- 质量门：`pnpm check`、OpenSpec strict、`git diff --check`。
