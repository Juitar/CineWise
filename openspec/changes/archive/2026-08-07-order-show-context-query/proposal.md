# Change: 补充个人订单场次上下文

## 背景

个人订单列表和详情当前只返回 `showId`。A 的购票前端因此无法展示权威开场时间，也无法携带正确的 `movieId`、`cinemaId` 返回场次或选座页面。

## 范围

- A 在 `GET /api/v1/orders` 和 `GET /api/v1/orders/{orderNo}` 的每条订单记录中新增十进制字符串 `movieId`、`cinemaId` 和带业务时区偏移的 `showStartTime`。
- 三个字段只读取 A 拥有的 `movie_show` 场次事实，并保持现有本人订单过滤、分页、排序和 404 语义。
- 同步 OpenAPI、固定 JSON 夹具和自动化测试，为 A 的订单、支付和电子票页面提供稳定契约。

## 非范围

- 不新增或修改 Flyway、表、索引和种子。
- 不返回影片标题、海报、影院名称等 D 拥有的内容事实。
- 不修改建单、取消、支付、电子票、退款和出行补偿的写事务、状态机或锁定 SQL。
- 不修改 C 的认证、安全链、公共请求封装和前端壳层。

## Owner 与影响

- Owner：A。
- 消费者：A 的购票交易前端。字段为向后兼容的响应增量，前端不得根据 `showId` 猜测影片、影院或开场时间。
- 数据边界：只连接 `ticket_order` 与 `movie_show`，不访问 D 的内容 Mapper、Repository 或表。

## 验收结果

- 本人订单列表和详情均返回与 `movie_show` 一致的三个场次上下文字段。
- 跨用户详情仍返回 404，空分页仍返回空记录，不伪造场次上下文。
- 列表一次查询取得订单与场次主投影，座位继续批量加载，不产生 N+1 查询。
- 带 `FOR UPDATE` 的订单查询和全部交易写链路保持不变。
