## Context

NetStart 的 `ci=70` 表示长沙，但它是第三方内部城市 ID，不是标准行政代码。当前同步直接用 `ContentQuery.cityCode="70"`，导致数据库、快照和公开接口都只能由 `location=70` 命中；现有前端又只接受六位行政代码，因此真实影院无法在页面展示。

## Decisions

### 1. 公开代码固定为 `430100`

`ContentQuery`、`CinemaContent.cityCode`、数据库、快照键、REST DTO 和前端 URL 全部使用长沙行政代码 `430100`。

### 2. 供应商 ID 只存在于 HTTP 适配器

`RestClientNetStartRawClient` 在发送影院搜索请求时将 `430100` 映射为 `ci=70`。当前只支持长沙；收到其他行政代码时直接拒绝，避免把行政代码误传给第三方或产生错误城市数据。

### 3. 不增加临时兼容查询

不同时保存 `70` 和 `430100` 两套快照，也不让前端改用 `70`。重新同步后由 `430100` 的 LIVE 快照覆盖页面读取；旧 `70` 快照后续按既有生命周期过期，不扩大本 change 为数据清理任务。

## Test Strategy

- Provider 测试确认每日影院查询使用 `430100`，标准化结果保留 `430100`。
- HTTP 适配器测试确认 `430100 → 70` 且未知城市被拒绝。
- 前端参数和页面测试确认默认 URL、请求和文案为长沙 `430100`。
- 受控启动同步后验证同步审计、接口来源、数量和每条记录的 cityCode。
