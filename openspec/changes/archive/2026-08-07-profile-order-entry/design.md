## 实现方案

本次只增加前端路由链接，订单页面、订单模块 API 和 `.umirc.ts` 中的 `/orders` 路由不修改。

个人中心继续从 `AuthProvider` 读取 `currentUser`。只有 `currentUser` 存在时显示“我的订单”链接；资料意外缺失的提示页不显示受保护操作。

桌面端的 `DesktopTopBar` 已经根据 `status === 'authenticated' && currentUser` 显示用户菜单，因此在该菜单内增加订单链接。左侧导航由所有用户页面复用，组件同样读取认证状态，只对已登录用户添加订单项。移动端底部导航也读取认证状态，并在已登录时增加订单项。这样匿名用户不会从公共导航看到订单入口。

桌面与移动端继续共用 `/orders` 路径和现有认证守卫。导航只发起客户端跳转，不发起订单请求，不保存订单数据，也不改变未登录回跳规则。

## 状态处理

| 条件 | 页面行为 |
| --- | --- |
| `status` 为 `authenticated` 且有 `currentUser` | 显示个人中心、桌面和移动端订单入口 |
| `status` 为 `anonymous`、`checking`、`error` 或没有当前用户 | 不显示公共导航订单入口 |
| 匿名用户直接访问 `/orders` | 保持 `RequireAuth` 现有登录跳转和 `returnUrl` 行为 |

## 测试方案

- 个人中心组件测试断言“我的订单”存在、链接地址为 `/orders`，并断言资料缺失时不显示。
- 桌面顶部菜单、桌面侧栏和移动底部导航组件测试分别断言认证用户可访问订单入口、匿名用户不显示。
- 移动端测试使用现有 `matchMedia` 测试工具验证 TabBar 在小屏渲染；不增加浏览器 Mock 或订单数据。
