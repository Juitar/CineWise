# 订单交易页面与过期释放修复

## 背景

现有 A 票务页面已接通订单交易主链，但退款影响页和替代场次页仍直接展示 ISO 时间；订单日期筛选仍依赖浏览器原生日期控件；部分终态页面缺少安全业务返回入口。替代场次查询还未限制为原影院，可能把其他影院的同影片场次展示为“同影院”候选。

## 范围

- A 前端统一格式化退款与替代场次的业务时间。
- A 前端使用 Ant Design `DatePicker` 提供空白初始值和统一日期格式。
- A 订单、支付、退款和支付结果页面提供安全业务返回入口。
- A 退票替代场次查询按原订单影院过滤，并补充回归测试。
- 在不修改仓库配置的前提下，对受控环境的订单过期调度进行验证并记录结果。

## 非范围

- 不修改 C 的公共请求层、认证、CSRF、错误解析或路由壳层。
- 不实现 D 的影片/影院内容接线，不访问 D 的持久化表。
- 不新增或修改 Flyway 迁移，不修改共享数据库结构。
- 不新增推荐座位或隐私协议业务。

## Owner

- A：订单/退款后端、订单交易前端、调度验证。
- C：公共错误解析（本 change 不修改，作为外部阻塞项）。
- D：内容详情查询方式（本 change 不修改，作为外部阻塞项）。

## 验收

- 页面时间显示为 `YYYY-MM-DD HH:mm` 的中国业务时间。
- 订单日期筛选使用 AntD `DatePicker`，初始为空，选择后提交服务端日期筛选。
- 页面返回不回到旧建单 URL；终态和写页面均提供明确安全回退。
- 替代场次只返回原影院、同影片、排除原场次且仍可售的候选。
- 在受控调度窗口中，过期待支付订单进入 `EXPIRED`，其锁定座位释放；支付/取消并发边界不被破坏。
