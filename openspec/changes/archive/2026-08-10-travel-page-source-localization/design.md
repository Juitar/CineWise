## 方案

新增前端纯函数 `formatTravelSource(source, kind)`，按 `CONTENT`、`ROUTE`、`WEATHER` 三类来源分别维护中文名称。页面调用该函数后再渲染来源字段。

来源编码仍由后端 API 返回，前端不修改 DTO、接口参数、缓存或 Provider 调用；中文名称只用于页面展示。未知值统一返回“来源待确认”，避免新 Provider 编码直接出现在页面。

## 边界

- 继续使用页面现有的面包屑、数据时间、有效期、演示和降级提示。
- 不改变路线规划、提醒更新、用户定位和订单跳转。
- 不新增第三方依赖，不记录用户位置或原始地点。

## 测试

- 单元测试覆盖已知内容、路线、天气来源和未知来源。
- 页面测试确认天气与路线不再显示英文编码。
