# Proposal: cinema-detail-purchase-entry

## 背景

影院列表已经接入 `GET /api/v1/cinemas` 的真实基础资料，但影院卡片仍不可进入二级页面。现有购票前端已经支持 `/shows?movieId=&cinemaId=`、选座、建单和支付；当前缺口是用户进入某家影院后，无法先选择该影院有排期的影片，再进入已有购票流程。

后端已有公开影院详情接口 `GET /api/v1/cinemas/{cinemaId}`，但没有“按影院查询未来可售影片”的接口。前端不能下载全量影片后逐个请求场次，也不能根据影片目录猜测该影院是否可购，因此需要 A 提供聚合查询，D 提供影片展示摘要，C 完成详情页和入口。

长沙影院基础资料来自 LIVE 内容源，但现有本地排期主要关联固定 Mock 影院。本 change 明确接受演示排期，不要求接入第三方真实排片；A、D 只需为至少一家长沙 LIVE 影院建立明确标记为 Mock 的本地排期关联，使用户可以继续完成现有购票流程。其他真实影院没有 A 的 `ON_SALE` 场次时，仍只显示“暂无可售场次”。

## 目标

- 新增公开影院详情页 `/cinemas/:cinemaId`，展示影院基础资料和未来 7 天有可售场次的影片。
- 新增 `GET /api/v1/shows/available-movies?cinemaId=`，一次返回该影院可选影片及排期统计。
- 用户选择影片后跳转到现有 `/shows?movieId={movieId}&cinemaId={cinemaId}`，继续选场次、选座、建单和支付。
- 保持影院基础资料与排期数据的来源、更新时间和演示属性可见，不把 Mock 排期说成真实排期或实时库存。
- 为至少一家长沙 LIVE 影院准备可重复的本地演示排期，使演示环境能够从真实影院资料进入购票流程。
- 本期以完成选影片、选场次、选座、建单和模拟支付为验收目标，不要求排片、票价或库存来自第三方真实来源。

## 非目标

- 不重写场次列表、选座、建单、支付、订单或电子票页面。
- 不提供影院搜索、收藏、定位、距离计算、路线、影厅设施或评价。
- 不在影院详情页展示或推断起价、实时余座、影厅标签等票务事实。
- 不让 A 直接读取 D 的 Entity、Mapper、Repository、缓存或内容表。
- 不把历史或离线排期描述为当前可购，也不把演示排期描述为 Provider 提供的真实排期。

## Owner 与协作

- C：影院列表语义化入口、影院详情路由和页面、前端 API/DTO/Hook、状态处理、响应式和浏览器验收。
- A：`available-movies` 查询、未来 7 天排期统计、票务 DTO、OpenAPI、错误处理、测试和长沙演示排期。
- D：影院详情接口继续提供公开基础资料；扩展公开影片摘要 Application API，供 A 批量补齐标题和海报；协助 A 将明确的长沙 LIVE `cinemaId` 用于演示排期。
- A、D：通过公开 Application API 解析目标影院、影片内部 ID 并建立演示关联；这属于实现任务，不再等待是否允许使用 Mock 排片的产品决定。

## 验收

- 从 `/cinemas` 点击影院卡片可进入 `/cinemas/:cinemaId`，刷新页面仍能重新查询并展示。
- 页面显示影院详情；有排期时显示可选影片，选择后进入现有 `/shows` 页面。
- 无排期、影院不存在、影院查询失败和排期查询失败均有准确且可恢复的页面状态。
- 至少一家长沙 LIVE 影院在演示环境可看到明确标识的演示排期，并可继续完成已有购票流程。
- 其他没有本地可售场次的 LIVE 影院不显示购票按钮、价格或余座。
