# 本人出行路线 HTTP 接口

## 背景

现有 `BasicRouteService` 已能在后端按本人出行任务、一次性用户坐标和影院坐标规划路线，但浏览器没有可调用的 REST 接口。C 已确认页面只在用户点击后获取浏览器位置，并且首版只支持驾车和步行。

## 范围

- 新增 `POST /api/v1/travel/tasks/{taskId}/route`。
- 接收一次性 JSON 数值坐标、`DRIVING` 或 `WALKING` 和位置共享确认。
- 返回现有 `BasicRouteResult`，不返回起点、影院坐标或路线折线。

## 非范围

- 不保存坐标、确认记录或路线历史。
- 不新增持续定位、地点文本路线、公交路线或 Agent/SSE 改动。
- 不复用推荐模块的 `distanceContextId`。

## 负责人

- D：后端接口、OpenAPI、测试。
- C：出行页面定位、请求、Mock 和页面展示。

## 验收

- 有效本人任务在确认后可得到驾车或步行路线摘要。
- 任务无权/不存在为 `404/207001`，未确认共享为 `422/107002`，路线不可用为 `503/307001`。
- 请求和响应均不持久化或泄露精确坐标。
