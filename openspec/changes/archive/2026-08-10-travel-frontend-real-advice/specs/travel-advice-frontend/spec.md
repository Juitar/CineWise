# 真实观影提醒与出行页面

## ADDED Requirements

### Requirement: 页面只能展示服务端真实出行数据

系统 SHALL 通过任务 ID 查询当前用户的出行任务，并只展示任务详情和建议响应中的影院、天气、建议、提醒时间、来源、数据时间和有效期。系统 MUST NOT 展示写死的路线、距离、出发时间或餐饮数据，也不得调用定位、地图或第三方服务。

#### Scenario: 已生成建议

- **WHEN** 当前用户打开存在且属于本人的任务页面
- **THEN** 页面展示服务端返回的天气、建议、来源、数据时间、有效期和降级状态
- **AND** 不显示服务端没有返回的路线、距离或餐饮信息

#### Scenario: 建议尚未生成

- **WHEN** 建议响应的 `available` 为 `false`
- **THEN** 页面明确说明建议尚未生成并提供用户主动触发的刷新操作

### Requirement: 订单入口必须查询真实任务

系统 SHALL 只在已支付订单提供出行入口，并 MUST 使用订单响应中的 `orderId` 查询本人任务。系统不得根据订单号或页面状态猜测 `taskId`，也不得创建出行任务。

#### Scenario: 订单尚未建立出行任务

- **WHEN** 按订单查询返回 404 或 `207001`
- **THEN** 订单页面说明出行任务尚未建立或不可访问
- **AND** 页面保持当前订单内容，不导航到虚构任务

### Requirement: 页面必须正确处理失效和访问异常

系统 SHALL 对加载、空数据、建议失效、查询失败、任务不存在和无权限给出可操作提示。建议 `isExpired=true` 或任务为 `CANCELLED` 时 MUST 只读展示并禁止刷新和更新提醒。

#### Scenario: 失效建议

- **WHEN** 建议响应标记为 `isExpired=true`
- **THEN** 页面保留已有建议作为只读参考并说明已失效
- **AND** 不自动刷新或提交提醒更新

#### Scenario: 任务不存在或无权限

- **WHEN** 查询返回 HTTP 404 或业务码 `207001`
- **THEN** 页面不显示任务内容，并引导用户返回订单列表

### Requirement: 提醒时间更新必须防重复并支持结果恢复

系统 SHALL 使用 `PUT /api/v1/travel/tasks/{taskId}/reminder` 更新提醒时间，请求 MUST 同时使用当前 `version` 作为 `If-Match` 请求头和请求体字段。提交期间 MUST 禁止再次提交；写请求结果未知时 MUST 不自动重发，只能查询相同 `taskId` 恢复。

#### Scenario: 提醒时间更新成功

- **WHEN** 用户提交新的合法提醒时间
- **THEN** 页面使用响应中的 `triggerAt`、`status` 和 `version` 更新本地显示

#### Scenario: 写入结果未知

- **WHEN** 更新提醒时间因超时、网络失败或无法识别的响应导致结果未知
- **THEN** 页面禁止重复提交并提供“重新查询任务”操作
- **AND** 恢复操作只发送 GET，不重发 PUT

### Requirement: 刷新建议必须防重复并保留已有结果

系统 SHALL 在刷新建议请求进行中禁止再次刷新，并直接显示服务端返回的建议或固定错误。系统 MUST NOT 在刷新失败、断网或超时后自动重发，也不得清空此前成功展示的建议。

#### Scenario: 刷新受限

- **WHEN** 刷新返回 HTTP 429 或业务码 `107001`
- **THEN** 页面提示刷新过于频繁并保留当前建议

#### Scenario: 刷新冲突

- **WHEN** 刷新返回 HTTP 409 或业务码 `207002/207003`
- **THEN** 页面提示任务状态已经变化并允许重新查询

### Requirement: 本期不提供关闭提醒

系统 MUST NOT 显示关闭或重新开启提醒的开关，也不得用远期时间、取消任务或本地状态伪造关闭提醒。

#### Scenario: 用户查看提醒设置

- **WHEN** 用户打开有效的出行任务页面
- **THEN** 页面只允许修改提醒时间
