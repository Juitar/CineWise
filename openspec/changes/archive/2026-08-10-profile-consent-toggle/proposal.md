# 个人中心画像数据使用开关

## Why

个人中心目前只有 D 的“开启个性化”开关。未同意画像数据使用时，页面只能显示 `202004` 提示，用户无法从个人中心作出独立同意；也无法用一个明确入口撤回同意。

## What Changes

- 在个人中心增加独立的“使用用户画像”开关，与“开启个性化”明确区分。
- 开启时调用 C 已提供的画像数据同意写接口，并刷新 D 的画像标签和个性化结果。
- 关闭时调用 C 已提供的撤回接口，立即清空页面画像数据。
- 继续通过现有画像 REST 的成功或 `202004` 判断页面开关状态，不新增查询同意状态 REST。
- 对提交中、冲突、结果未知、401、422 和 5xx 提供明确状态，写请求不自动重发。

## Non-Goals

- 不修改同意记录、outbox、D 的画像清理、Redis 或数据库迁移。
- 不修改标签编辑、推荐算法、Agent 或出行功能。
- 不把注册隐私政策同意或个性化开关当作画像数据使用同意。

## Owner 与影响

- C：维护个人中心页面、`modules/profile` API 和 Hook。
- D：画像 REST 和 `202004` 规则保持不变，不需要修改 D 的后端实现。
- 复用已合并的 `PUT/DELETE /api/v1/auth/profile-data-consent`，不改变跨模块接口。

## Acceptance Results

- 未同意用户能在个人中心打开画像数据使用，成功后读取并展示画像区域。
- 已同意用户能关闭画像数据使用，成功后页面不再展示旧标签和个性化结果。
- 个性化开关只在画像数据使用已开启时显示。
- 网络或服务异常不把未知状态显示成已开启，也不自动重复同意或撤回请求。
