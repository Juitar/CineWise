# 三栏 Agent 推荐方案工作区

## 背景与目标

首页 Agent 当前进入全屏 `/assistant`，与前端设计中“左导航、方案区、右侧 Agent”的正常用户入口不一致。本 change 新增推荐方案工作区，复用现有 Agent 会话、SSE、恢复、确认和选座意图处理。

## 范围

- C 新增受登录保护的 `/recommendations` 与 `/recommendations/:sessionId`。
- 首页 Agent 输入进入新工作区，`/assistant` 保留为开发调试页。
- 桌面端在全局左导航右侧展示真实方案区和 Agent 对话区；移动端使用同一 Hook 和投影做单列布局。
- 中间区只展示最新 `PLAN_CARD` 的最多三个白名单方案，支持选择、二次提问和调整。
- 只有已校验的 `BUSINESS_INTENT SELECT_SEATS` 可以显示现有选座入口。

## 非范围

- 不修改 B 的 Agent 后端、消息请求 DTO 或计划规则。
- 不修改 A 的场次、选座和交易规则。
- 不接入 D 的地图、路线、附近餐饮，也不补静态假数据。
- 不做座位推荐，不把 `PLAN_CARD` 快照当作可购票或可支付结果。

## 负责人和影响

- 负责人：C。
- B 继续保证会话上下文能理解“当前最新推荐中的第 N 个方案”；若需要结构化方案引用，由 B 另行提供正式协议。
- A 的 `SELECT_SEATS` 路由和 D 的出行能力不变。

## 验收结果

- 首页 Agent 登录后进入新工作区并自动提交首页草稿。
- 桌面和移动端共享一个 Agent Hook、DTO、投影与恢复流程。
- 真实 `PLAN_CARD` 在方案区展示，选择后可在右侧解释或继续调整。
- 未收到正式 `SELECT_SEATS` 时没有“去选座”；收到后复用现有白名单路由。
