## Why

当前系统没有可持久化、可修改和可关闭的用户画像。固定推荐只能按本次输入筛选，无法在用户明确开启个性化后参考其长期偏好；同时也不能把一次性的对话表达或原始行为记录直接暴露给 Agent。

## What Changes

- 在 D 的 `profile` 模块实现个性化开关、本人标签管理、最小化画像摘要和行为事件接收。
- V010 已创建并发布 `user_preference`、`user_profile_tag`、`user_behavior_event`、`profile_write_request` 四张 D 负责表；`profile_write_request` 仅用于画像写请求的幂等恢复，不作为通用审计表。V010 已冻结，后续结构调整只能新增向前迁移。
- 提供个人中心 REST 接口，以及仅供 B 调用的 `GetProfileSummaryTool`；摘要只在个性化开启时返回有效标签。
- 让推荐模块能够取得并实际使用受控摘要；推荐结果使用 `usedProfile` 和最小标签证据说明是否采用画像，本 change 不改 B 的 Agent 运行、SSE、确认页面。
- 覆盖首次默认开关、单标签停用/恢复、分页查询和个人数据保存同意撤回后的画像停用与清理，以及画像使用审计所需的最小结果字段。
- 采用用户版本、`If-Match`、`Idempotency-Key`、行为 `eventId` 和数据库唯一约束处理重复写入、并发编辑与行为重放。
- 新增画像写请求记录，保证同一操作的相同 `Idempotency-Key` 能在进程重启后返回首次响应；保存画像前校验 C 提供的个人数据保存同意状态。

## Non-Goals

- 不实现 B 的 Agent 会话、确认交互、SSE、运行轨迹或 `agent_*` 表。
- 不实现 C 的认证、用户资料、前端页面、公共请求层或邮件能力；D 不读取 `sys_user` Repository。
- 不保存密码、验证码、邮箱明文、精确位置、路线几何、完整对话、模型推理过程或跨用户画像。
- 不生成影片语义标签、不创建订单、锁座、支付、退票或场次事实；不把长期画像覆盖用户本轮明确要求。
- 不在本次 change 中接入真实画像算法、广告画像、跨端画像同步或自动化模型推断。
- 当前版本不实现账户注销、账户删除或账户删除通知；登录和退出登录也不触发画像停用或清理。

## Impact

- D：新增 `profile` 的 api/application/domain/infrastructure 分层、缓存、定时过期处理和测试。
- A：审核 D 的 V010 草案，并在明确授权后在隔离 MySQL 验证四张画像表迁移。
- B：本期通过 `ToolContext` 预取 `GetProfileSummaryTool`，并在确认动作最终保存后调用方案接受/拒绝反馈；长期对话偏好写入不在本期范围。
- C：确认 `CurrentUserAccessor` 的接入方式，并在后续单独任务中对接画像页面、版本冲突提示和 API 类型。
- 推荐：D 将 `ProfileSummary` 作为可选特征接入确定性评分，并记录本次是否使用画像及使用的标签证据；本轮明确要求仍优先。

## Acceptance Results

- 用户只能查看和修改自己的标签与开关；关闭后下一次摘要查询只返回 `enabled=false`。
- 显式偏好不会被单次行为覆盖；重复行为事件不会重复累加。
- 画像摘要不包含原始行为、对话、精确位置或其他用户数据。
- 并发编辑返回最新版本，不会静默覆盖；缓存会在写入后失效。
- 首次读取能得到默认开启的画像设置；用户可停用或恢复单个标签；个人数据保存同意撤回后画像立即停止使用并进入受控清理。
- 迁移、权限、幂等、衰减、关闭开关、工具最小化输出和推荐兼容性均有可执行测试。
- 无有效同意状态、来源不可信的行为事件、重复撤回通知和 Redis 不可用等场景均不会写入或泄露画像数据。
