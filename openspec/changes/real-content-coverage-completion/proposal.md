## Why

`real-content-provider-integration` 已把 NetStart 的影片、影院基础资料同步到缓存和快照，但用户可见的真实资料仍不完整：影片海报和简介被丢弃；影院页、首页仍直接写死旧的杭州演示内容；影院城市条件混用了 Provider 的 `ci` 与系统行政区划代码；同步只覆盖热映，且管理端无法查看或手动触发同步。当前还把影片、影院资料按 6 小时有效、7 天最大陈旧处理，导致已取得的真实资料会在短期故障后让位给 Demo，不符合“真实历史资料优先于固定演示资料”的目标。

本变更补齐“真实影片和影院基础资料从 Provider 到页面”的缺口。它不把真实内容误当成真实票务，场次、票价、库存、座位和交易仍由 A 的本地票务能力负责。

## What Changes

- 补齐影片海报、简介、上映状态/日期等 Provider 可提供的基础字段；海报地址必须在 D 的适配层规范化为 HTTPS，再进入 `MovieContent`、快照、缓存和 `MovieResponse.posterUrl`。
- 将 NetStart `cities.json` 经受控核验后保存为仓库内版本化城市目录；应用启动时加载到内存，用户请求不访问该第三方接口。
- C 通过 `POST /api/v1/content/cities/resolve` 提交临时 `locationText`，D 只返回受控状态和城市名；B 的 Agent 对话仅将地点文本作为本次 D 调用的内存参数。D 从地点字符串解析唯一城市名，再用本地城市目录取得 Provider `ci`；不能解析或存在多个城市候选时明确返回不可用或待选择，绝不猜测。地点原文不落库、不进缓存、日志、快照或画像；B 在保存 Agent 消息、事件、槽位快照、长期上下文、日志和缓存前必须剔除或替换它。
- 补齐影院按城市同步和查询：页面只传、只显示城市名，Provider `ci` 只在 D 的外部调用边界使用；不再将中国行政区划代码作为城市选择和 NetStart 转换的前置条件。
- D 将已解析且已同步的城市转换为本地 `cinemaIds`；A 不接收地点字符串、城市名、城市代码或 NetStart `ci`。D 只把 `date + cinemaIds` 交给 A 后续新增的公开只读场次 Application API。
- 扩展 D 的公开批量影院摘要端口：返回 `cinemaId/name/address/source/dataTime`，并区分“部分影院 ID 无结果”的正常批量结果与“内容摘要整体不可用”的错误；A 只能通过该端口聚合影院展示资料。
- 补齐热映与待映的受控同步、字段质量和去重规则；未通过校验的数据不能覆盖已验证快照。
- 取消影片、影院基础资料按时间淘汰的规则：每个公开查询保留最新两次完整成功的真实资料版本，最新版本优先、上一版本兜底。真实资料无论距今多久都优先于 Demo，并明确显示最近同步时间和“正在展示最近成功同步资料”。
- 移除每日同步中由 10 req/min 保护值间接造成的“最多 8 部影片详情”上限。NetStart 未提供可验证的近一年历史目录，本期只同步其当前可取得的热映目录；详情按不超过 10 req/min 的可恢复批次处理，页面仅在已同步的真实目录中分页、搜索和筛选，不把该目录表述为近一年完整片库。
- 开发环境默认启用已确认的 NetStart Provider，并由每天凌晨 3 点的定时任务同步真实影片、影院资料；不使用启动即同步作为常规更新方式。开发排障可显式关闭开关，生产或商业环境仍强制关闭该学习用途 Provider。
- 补齐按当前城市浏览影院：本期默认长沙并支持用户手动选择城市；C/B 提供地点字符串时，D 解析后切换城市。浏览页不计算距离，定位仅保留给用户主动发起的基础路线。
- 在没有城市输入时，页面默认使用长沙；该值只属于当前页面会话，不保存为用户偏好。
- 增加管理员可查询的内容来源状态和按城市受控手动同步；Provider 城市 ID 可留在服务端审计数据，但不出现在公开响应。不同步地点原文、Key、完整原始响应或受限文本。
- 增加仅供 A 后续使用的公开内容身份解析契约：按 `provider + resourceType + externalId` 批量唯一解析内部 `movieId/cinemaId`；明确输入校验、数值错误码、映射失效和歧义处理，不暴露 D 的 Entity、Mapper、Repository 或内容表。
- 由 C 将影院页和首页的影片/影院展示替换为已确认的内容 API；删除写死的杭州影院、演示距离、演示场次和演示起价。真实影片/影院没有 A 的可售场次时，页面只展示基础资料和无场次状态。
- 补齐 D、C、A 的测试、OpenAPI/类型、Mock 和真实开发环境验证材料。

## Non-Goals

- 不接入影评正文、用户评论、演员等未确认展示字段，不保存 Provider 原始响应。
- 不接入真实排期、真实影厅、实时库存、真实座位、真实订单、支付或退款；不以真实内容推断这些数据。A 负责新增 `date + cinemaIds` 的公开只读可售场次 API，并在其 OpenSpec 中定义余座、数量上限、排序、超限和错误返回；D 只消费该 API 的查询快照，建单仍由 A 重新校验。
- 不在本 change 创建或迁移 `movie_tag`、`recommendation_record`；推荐历史范围和两表完整设计未定，后续另行提出 change 和迁移申请。
- 不自动选择新的第三方数据源，不在生产或商业环境启用仅供学习用途的 NetStart。
- 不保存用户地点原文、精确位置、位置授权结果或距离排序记录；它们不进入 MySQL、Redis、日志、快照、URL、画像或 Agent 轨迹，也不做持续定位。

## Owners and Required Decisions

- D：本地城市目录、地点字符串解析、Provider 映射、内容模型、缓存/快照、按城市同步、来源状态、质量校验和后端测试。
- A：为新增影片持久化字段分配并验证 Flyway 版本；确认真实内容与本地 Mock 场次的展示边界不变。
- A：已确认当前真实影片、影院任务不等待真实排期；后续真实排期数据源、`movie_show`、座位、价格和下单入口由 A 的独立 change 负责。
- A：新增按业务日期和 D 传入 `cinemaIds` 查询可售场次的公开只读 Application API；A 在自己的 OpenSpec 中确认余座大于零、数量上限、稳定排序、超限、无结果和查询不可用规则。
- C：确认 `posterUrl`、`summary`、上映状态/日期及来源时效字段；提供手动选择或浏览器侧已得到的临时地点字符串，接收 D 返回的城市名并查询影院；完成管理员按城市同步交互。
- B：地点字符串仅在用户明确提出地点时传给 D 的城市解析能力；不把它写入 Tool 轨迹或长期上下文。B 复核新增输入输出不含精确位置和票务事实。

## Acceptance Results

- 已同步且合格的真实影片，在 `GET /api/v1/movies` 和详情接口中可返回 HTTPS `posterUrl`；前端能显示海报或在空/加载失败时显示占位。
- 已同步且 Provider 可提供的影片简介、上映状态/日期和影院坐标可经标准化、缓存、快照和 REST 一致读取；Provider 缺字段时按字段规则为空或拒绝该条，不伪造值。
- C/B 提供“长沙市岳麓区”等地点字符串时，D 能解析为唯一城市“长沙”、用本地目录取得 `ci=70`，并查询或同步长沙影院；用户请求不访问 NetStart 城市列表。
- 未选择城市时展示长沙，用户手动选择或 D 解析为杭州后只查询和展示对应城市影院；无法解析或未同步的城市明确显示暂无法查询，不展示其他城市资料。本期影院浏览不展示距离。
- 城市切换仅保留当前页面会话，不作为用户长期偏好保存。
- 首页、影片页和影院页不再把写死的虚构影片/影院当作真实数据展示；来源、同步时间、资料版本和降级提示保持正确。
- 管理员可查询最近同步状态，并能按确认后的限制发起一次同步；非管理员无权访问。
- 真实内容与 A 的 Mock 场次分开显示，未关联可售场次的真实内容不能显示价格、余座或“可购”。
- A 可通过 D 的公开身份解析契约安全取得内部影片、影院 ID；未匹配、重复或有歧义时不返回猜测结果。
- A 可一次解析同一来源、同一资源类型下最多 100 个外部 ID；未匹配、歧义或已失效的映射逐项返回稳定数值码，不影响同批其他有效结果。
- A 的按城市可售影院聚合可经 D 的批量影院摘要端口取得名称、地址、来源和时间；部分影院缺失不阻断其余影院，内容摘要整体不可用时返回固定错误，不伪造空结果。
- 在任意一次真实影片、影院同步成功后，后续查询优先使用保留的真实版本；Demo 只在首次尚无真实版本、明确切换演示模式或两份真实版本均不可恢复时使用。
- 开发环境每天凌晨 3 点自动同步；同步失败不清空已经成功保存的两份真实资料版本。
- 当前可取得热映目录同步完成后，用户翻页、搜索和筛选均只查询本地目录，不因用户请求直接访问 Provider；目录范围明确标为当前可取得热映资料，不表述为近一年完整片库。
