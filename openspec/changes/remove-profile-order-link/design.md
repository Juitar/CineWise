## 实现方案

个人中心保留指向 `/orders` 的 `Link`，并使用 `.profile-orders-link` 与既有账号操作按钮保持一致。`/orders` 是现有 `RequireAuth` 保护的独立页面，作为用户从个人中心进入订单后的下一层页面；本次不修改订单页路由、数据查询或返回逻辑。

桌面侧边栏删除订单菜单项，同时清理只为该菜单项存在的认证状态读取和订单选中态。桌面用户菜单和移动端底部导航也删除订单入口及仅服务该入口的图标、认证状态读取；公共导航只保留进入个人中心的入口。

## 测试方案

- 个人中心组件测试断言已登录用户可进入 `/orders`，资料缺失时不显示该链接。
- 公共导航组件测试断言已登录用户在桌面侧边栏、桌面用户菜单和移动端底部导航均看不到订单入口。
- 执行相关 Vitest、OpenSpec 严格校验和 Git 差异检查。
