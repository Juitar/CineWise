# Change: 补齐购票交易页面出口

## 背景

当前建单成功页仍停留在第一批提示，只显示订单号和“下一迭代”文案，用户无法直接进入支付或订单详情；支付成功页也没有电子票入口。后端订单、支付和电子票链路已具备，前端需要以服务端返回的 `orderNo` 和 `ticketId` 完成用户可达闭环。

## 范围

- 建单成功后提供“去支付”和“查看订单”出口，使用服务端返回的 `orderNo` 构造路由。
- 支付成功且 `PaymentResponse.ticketId` 存在时提供“查看电子票”出口；没有票号时不伪造入口。
- 保持支付、建单、RESULT_UNKNOWN 和认证的既有边界，不新增写请求或自动跳转。
- 补齐页面编排、路由构造和端到端验收。

## 非范围

- 不修改 C 的公共请求层、认证、路由守卫和 `.umirc.ts`。
- 不修改后端 API、数据库、订单/支付/电子票状态机或支付密码处理。
- 不实现首页、影院或影片内容入口；该能力需要 C/D 的公开内容数据与页面接入。

## Owner 与协作

- A：页面逻辑、路由、模块接线、E2E 和 OpenSpec。
- 前端展示 AI：仅实现 `OrderCreateSuccess` 与 `PaymentResult` 的展示 Props、视觉与组件测试，不处理请求或路由。
- 依赖：以 PR #70 的交易展示修正为基线；UI 组件合入前不提前声称支付成功电子票入口已完成。
