# 设计

## 调用边界

`DemoSeedInitializer` 只通过 `ContentPurchaseQueryPort.findLiveDemoPurchaseCatalog("430100")` 取得稳定的本地影片/影院引用。D 的内容实现和持久化细节不进入 A 模块。

## 种子流程

1. 启动时只保留固定 Demo 内容和票务种子，避免重启时按真实影院目录批量写入。
2. 每日 03:10 查询真实目录；经 D 于 2026-08-09 确认，A 仅为本地演示排期引用按 `dataAt + 24h` 计算窗口，即使内容表原始 `expiresAt` 更早也可在该窗口内引用。影片、影院展示仍使用 D 的原始 `expiresAt`，不由 A 改写。两侧目录任一超过该 24 小时窗口时，不调用 A 票务种子服务。
3. 每家影院复用 1 个 Mock 影厅，并只生成当天和次日的早晚两场、每场 40 座；来源标记为 `demo-seed`/`MOCK`。
4. 票务查询层已有规则：同影院同业务日期存在 `external-sandbox` 时过滤同日 `demo-seed`；不删除或覆盖任一来源的交易数据。
5. 每日任务先分批清理已结束、无订单且所有座位均未锁定的 `demo-seed` 场次，再补齐新的两天窗口。

## 幂等与状态保护

场次以影厅和开场时间为自然业务键，座位只补缺失业务键。重复任务不生成重复场次，不更新已有座位的锁定、售出、订单号或版本。候选查询先排除已有订单和非 AVAILABLE/带锁座位，避免历史交易场次耗尽单次批量额度；候选不是删除依据：同一事务内仍须锁定场次和全部座位，再锁定并检查订单记录。锁定后的座位只要不是 AVAILABLE 或仍有锁信息、或存在订单即跳过。只有复核通过才删除座位图和场次，并按场次实际删除行数计数。

## 测试

- 多家真实影院全部生成 Mock 排期。
- 目录为空或过期不新增排期。
- 同影院同日真实沙箱优先、其他日期保留 Mock。
- 重复运行保持数量和已锁座状态不变。
- MySQL 并发测试覆盖“候选读取后发生锁座”的竞争；清理必须等待并复核，不能删除该场次或座位。
- 原始 `expiresAt` 早于 `dataAt + 24h` 时，验证仅 A 的演示引用窗口仍有效，且不改变 D 的页面展示时效语义。
- 批量候选测试覆盖最早 100 条均有订单时，下一条无交易关联的场次仍可被选中并清理。
