# 设计

## 调用边界

`DemoSeedInitializer` 只通过 `ContentPurchaseQueryPort.findLiveDemoPurchaseCatalog("430100")` 取得稳定的本地影片/影院引用。D 的内容实现和持久化细节不进入 A 模块。

## 种子流程

1. 先保留固定 Demo 内容和票务种子，确保无真实目录时仍有最小演示链路。
2. 查询真实目录；只有 `movies`、`cinemas` 非空且 `expiresAt` 晚于当前业务时间时，才调用 A 票务种子服务。
3. 使用真实内容 ID 创建/复用 A 的 Mock 影厅、场次、座位和本地价格；来源标记为 `demo-seed`/`MOCK`。
4. 票务查询层已有规则：同影院同业务日期存在 `external-sandbox` 时过滤同日 `demo-seed`；不删除或覆盖任何真实场次和交易座位。

## 幂等与状态保护

场次以影厅和开场时间为自然业务键，座位只补缺失业务键。重复启动不生成重复场次，不更新已有座位的锁定、售出、订单号或版本。

## 测试

- 多家真实影院全部生成 Mock 排期。
- 目录为空或过期不新增排期。
- 同影院同日真实沙箱优先、其他日期保留 Mock。
- 重复运行保持数量和已锁座状态不变。
