# Design: cinema-detail-purchase-entry

## 页面和调用关系

`/cinemas` 的影院卡片使用语义化 `Link` 进入 `/cinemas/:cinemaId`。详情页从路由读取字符串 `cinemaId`，并行调用：

1. `GET /api/v1/cinemas/{cinemaId}` 获取影院名称、区域、地址、内容来源和更新时间；
2. `GET /api/v1/shows/available-movies?cinemaId={cinemaId}` 获取该影院未来 7 天有可售排期的影片。

两个请求共享公共请求层，但状态相互独立。影院请求失败时页面不能继续把影院描述为已加载；排期请求失败时保留已成功的影院资料，并在影片区域提供单独重试。路由参数变化或快速返回再进入时，旧请求结果不得覆盖新影院。

## 按影院查询可售影片

A 在 ticketing 模块实现公开查询。查询窗口按 `Asia/Shanghai` 和注入的 `Clock` 计算，从当前时刻到未来第 7 天窗口结束，只统计：

- `movie_show.cinema_id` 等于请求 `cinemaId`；
- `status=ON_SALE`；
- `start_time>now`；
- 场次仍位于未来 7 天查询窗口。

按 `movieId` 聚合 `showCount` 和 `nearestStartTime`。A 通过 D 的公开影片摘要 Application API 批量补齐 `title`、`posterUrl`、内容来源和内容时间，不访问 D 的持久化实现。批量接口一次读取影片目录后按内部 ID 过滤，不能对每个 ID 分别等待缓存连接；影片摘要无法取得时，该项不得以空标题进入正常结果，A 应记录可排查原因并排除该项，不能按名称猜测。

接口成功响应的 `data` 为：

```json
{
  "movies": [
    {
      "movieId": "10001",
      "title": "流浪地球",
      "posterUrl": "/demo/poster/10001.webp",
      "showCount": 6,
      "nearestStartTime": "2026-08-05T19:30:00+08:00",
      "dataSource": "demo-seed",
      "dataTime": "2026-08-05T10:00:00+08:00"
    }
  ]
}
```

`movieId` 为十进制字符串，`showCount` 为正整数，时间为带偏移 ISO 8601。结果按 `nearestStartTime` 升序、`movieId` 升序稳定排列。无匹配场次返回 HTTP 200 和 `movies=[]`。缺失、空白或格式非法的 `cinemaId` 返回 HTTP 400 / `100001`。

## 真实影院和演示排期

影院名称、地址等基础资料继续来自 D 的 LIVE 内容数据。排期、价格和座位由 A 管理，不能因为影院基础资料为 LIVE 就称排期也为 LIVE。

为了支持长沙现场演示，系统直接采用“LIVE 影院基础资料 + Mock 票务数据”的组合，不再等待真实排片来源。D 通过公开身份解析 Application API 返回一家具名长沙 LIVE 影院及演示影片的内部 ID；A 使用这些 ID 生成可重复的 Mock 影厅、场次和座位。种子不得修改 D 的影院基础资料，不得按影院名称或地址模糊匹配，并且重复执行不得覆盖已锁定或已售座位。

当 `dataSource` 表示 `demo-seed` 或其他 Mock 来源时，前端在影片区域显示“演示排期”。演示排期可以继续进入选场次、选座、建单和模拟支付，这就是本期要求的完整购票流程。没有 A 的可售场次时，页面只显示影院资料和“未来 7 天暂无可售影片”，不显示价格、余座或购票按钮。

## 前端结构

C 在现有内容模块中复用 `CinemaDetail`，新增按影院查询可售影片的 DTO、API 方法和 Hook。PC 与移动端共享 API、DTO、Hook 和数据状态，只调整布局。影片卡片至少展示标题、海报、场次数、最近开场时间、排期来源和数据时间；海报缺失或加载失败时使用现有占位图。

影院详情展示名称、区域、地址、内容来源和更新时间。页面不得展示伪造距离、路线、起价、余座或影厅标签。所有可操作目标在触控布局中不小于 44px，并保留键盘焦点样式和语义化链接。

选择影片只负责跳转到 `/shows?movieId={movieId}&cinemaId={cinemaId}`。现有场次页必须重新查询场次，选座和建单继续重新校验服务端状态、价格和库存，不能信任详情页的 `showCount` 或最近开场时间快照。

共享环境的 CSRF Cookie 会在写请求响应后更新。公共请求层收到任意写请求响应后必须清除内存中的旧 Token，让下一次写操作重新调用 `/api/v1/auth/csrf`；不得因自动重放原建单或支付请求来规避 `201009`。

## 状态和错误

- 首次加载：影院资料和影片区域分别显示骨架或加载状态，避免空白页。
- 影院 404：显示“影院不存在或已下线”和返回影院列表入口。
- 影院查询失败：显示错误和重试；不得展示旧影院资料冒充本次结果。
- 影片空数组：保留影院资料，显示未来 7 天暂无可售影片。
- 排期查询失败：保留影院资料，在影片区域显示失败原因和单独重试。
- 离线：使用公共请求层的网络错误分类，保留已成功渲染的基础资料，不伪造新排期。
- 刷新和竞态：所有状态由 URL 和服务端重新恢复；旧 `cinemaId` 的响应不得覆盖当前页面。

## 验证

A 增加查询服务、Controller、OpenAPI 和真实 MySQL 集成测试，覆盖正常聚合、稳定排序、空数组、非法参数、时间边界、非 `ON_SALE` 和已开场过滤。演示种子测试覆盖明确影院身份、重复执行和非 `AVAILABLE` 座位保护。

C 增加 API/Hook 单元测试和页面浏览器测试，覆盖加载、空态、404、两个请求的部分失败、重试、刷新、快速切换、离线、PC/移动布局、键盘访问及从影院列表到 `/shows` 的完整跳转。最终 HTTP 验收使用真实后端和数据库，并记录返回数据来源；浏览器必须实际完成登录、选座、连续建单与支付写请求以及电子票展示，前端静态 fixture 只用于自动化测试，不算真实联调完成。
