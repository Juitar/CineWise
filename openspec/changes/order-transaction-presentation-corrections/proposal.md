# Change: 订单交易展示权威性修正

## 背景

已归档的购票交易前端已经接入订单、支付、电子票和退票接口，但仍有两类展示会误导用户：支付页使用固定“15分00秒”而非订单 `expireTime`，订单详情与电子票把后端 `seatIds` 当作物理座位标签展示。订单状态和时间文案也分散在多个组件，后续容易出现同一权威状态的不同解释。

## 范围

- 在 `modules/order` 中集中维护订单、支付、电子票和退款状态的中文展示语义。
- 根据订单查询返回的 `expireTime` 生成支付剩余时间文案；浏览器时间只用于倒计时展示，不改变订单权威状态。
- 统一订单截止时间、更新时间和出票时间的 `Asia/Shanghai` 展示。
- 将 `seatIds` 明确作为“座位编号”展示，不伪造成排号、列号或座位标签。
- 对接前端展示组件完成支付、订单详情和电子票页面接线与回归测试。

## 非范围

- 不修改订单、支付、电子票或退款后端 DTO、接口、状态机和数据库。
- 不修改 C 的路由、认证、公共请求层、布局、全局网络状态或测试配置。
- 不接入 D 的影片标题、海报和影院名称，也不根据 ID 伪造内容事实。
- 不由浏览器倒计时判定订单已过期或触发任何支付、取消、退款写操作。

## Owner 与验收

- Owner：A；展示组件视觉调整可由前端 AI 在独立分支完成，最终真实数据接线、测试与交付由 A 负责。
- 支付页不再出现固定十五分钟；有效截止时间按秒更新，缺失或非法时间明确降级。
- `seatIds` 只按“座位编号”展示；状态和时间文案由 `modules/order` 统一提供。
- `pnpm check`、相关页面/模块测试、OpenSpec strict 与 `git diff --check` 通过。
