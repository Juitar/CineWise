# Design: 订单交易展示权威性修正

## 分层与协作

- `modules/order` 负责解析后端时间、计算只读倒计时、集中状态文案和座位编号展示语义。
- `pages` 只把 Hook 与格式化结果传给 `features`，不自行计算截止时间或解释状态。
- `features` 只渲染父级传入的支付期限、座位编号和状态，不调用 API、不改变交易状态。
- C 的 `.umirc.ts`、`shared/**`、认证、布局和全局离线能力保持不变。

## 支付期限

订单 `expireTime` 是支付期限的唯一服务端来源。模块按 `Asia/Shanghai` 解释不带偏移量的业务时间，并以当前浏览器时间计算展示用剩余秒数：

- 剩余时间大于零时，展示按秒递减的时长；
- 已到或超过截止时间时，提示刷新订单状态；
- 时间缺失或非法时，展示“支付期限以订单信息为准”；
- 页面卸载或订单切换时清理定时器。

该倒计时不是订单状态机。即使本地时间已超过截止时间，前端也不得把订单改成 `EXPIRED`；刷新、支付拒绝与最终状态均以服务端查询为准。

## 状态与座位语义

- `OrderStatus`、`PaymentStatus`、`ElectronicTicketStatus`、`RefundStatus` 的中文文案由模块中的完整类型映射集中维护，新增枚举值时 TypeScript 必须提示未覆盖。
- 颜色、图标与响应式布局仍属于展示组件。
- 当前公开订单和电子票 DTO 只返回 `seatIds`，因此页面只能标注为“座位编号”。没有权威行列快照时不得显示“A排01座”等物理标签。

## 验证

- 纯函数测试覆盖未来、恰好截止、已截止、跨小时、非法时间和无偏移业务时间。
- Hook 测试覆盖按秒更新、订单切换和卸载清理。
- 页面测试覆盖支付期限传值、截止/更新时间格式化及座位编号语义。
- 全量执行前端质量门和 OpenSpec/Git 检查。
