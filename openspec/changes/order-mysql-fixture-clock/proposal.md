# 订单 MySQL 并发测试时间夹具修复

## 背景

支付和退款 MySQL 并发测试启用固定种子 `20260802`，却以数据库实际当前时间筛选场次。日期推进后，种子场次全部成为已开场场次，测试在建单前失败，不能再验证支付或退款的并发语义。

## 范围

- A 将两个 MySQL 测试的业务 Clock 固定为与种子一致的时刻。
- 场次筛选使用同一个固定业务时间，而非数据库当前时间。
- 保持测试仅运行于 A 的隔离 MySQL 库，保留现有并发、幂等和状态断言。

## 非范围

- 不修改订单、支付、退款、场次或座位的生产业务代码。
- 不修改 Flyway、种子规则、API、事件或其他 Owner 模块。

## 验收

- 在任意执行日期，两个测试均能选中相对于固定业务 Clock 的可售场次。
- MySQL 8.4 下支付并发与退款并发测试均通过。
