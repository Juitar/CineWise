# Agent 交互卡片

## 背景与目标

PR #160 已提供 `QUESTION`、完整 `PLAN_CARD`、`BUSINESS_INTENT` 和确认卡正式 DTO，但当前前端仍把问题选项作为只读文本，把推荐方案压成通用字段列表。本变更由 C 使用已合并 DTO 完成可交互、可恢复的 Agent 卡片。

## 范围

- `QUESTION` 展示快捷选项和自由文本输入，并通过现有消息流提交答案。
- `PLAN_CARD` 按服务端顺序展示最多三个真实方案，以及理由、价格、时间、评分、距离、来源和有效状态。
- `BUSINESS_INTENT + SELECT_SEATS` 继续只使用已校验的 `showId/movieId/cinemaId` 进入固定选座页。
- 复用现有确认、拒绝和结果未知恢复逻辑，不新增确认写请求。
- 补协议校验、投影、组件和工作区测试。

## 非范围

- 不新增 `TRAVEL_ADVICE_CARD`、`ROUTE_CARD`、退票确认或其他后端尚未提供的正式 DTO。
- 不修改后端、SSE 事件、数据库、推荐排序、选座页或出行页。
- 不从自然语言、历史文本或未声明字段推断业务 ID、价格、路线或可购状态。

## Owner 与影响

C 负责前端实现。B 提供的卡片 DTO 和消息提交接口、D 提供的方案字段、A 提供的选座路由与场次复核保持不变；本变更不要求其他 Owner 新增接口。

## 验收结果

- 用户可在未过期问题卡上选择快捷答案或提交自由文本，同一次操作不会重复发送。
- 推荐方案以独立卡片展示完整的正式字段，空方案、降级、过期和不可购状态有明确提示。
- 卡片组件只接收安全投影；未知字段、内部 ID 和原始 payload 不进入页面。
- 现有确认卡、SSE 恢复和选座入口无回归。
