# 通过邮箱验证码重置密码

## 背景

PRD 和认证设计要求用户在忘记密码时通过邮箱验证码重置密码。现有认证实现只有 `REGISTER`、`LOGIN` 验证码用途，缺少 `RESET_PASSWORD`、重置接口、页面和旧会话失效处理。

## 范围

- C 在认证模块增加 `RESET_PASSWORD` 验证码用途，复用现有生成、HMAC 摘要、过期、冷却、尝试次数和一次性消费规则。
- C 实现 `POST /api/v1/auth/password/reset`，在同一事务中消费验证码、更新 BCrypt 密码摘要并递增 `tokenVersion`。
- C 实现 `/password/reset` 响应式页面、登录页入口、认证模块 API/Hook 和浏览器测试。
- C 更新 OpenAPI、错误映射、前端 DTO、Mock/测试夹具，并准备向前迁移申请和私下 SQL 草案。
- C 在自动测试完成后检查当前环境的真实 Redis、SMTP 和测试邮箱条件，只执行获得配置支持的受控验证。

## 非范围

- 不修改已经发布的 V011，不自行分配 Flyway 版本或执行共享数据库迁移。
- 不实现手机号找回、自动登录、旧凭据登录或密码重置邮件之外的业务。
- 不修改首页、影片、影院、Agent、D 内容/出行模块。

## Owner 与影响

- Owner：C。
- A：分配并审核向前迁移版本，决定何时进入共享数据库。
- 部署负责人：提供真实 Redis、SMTP、测试邮箱和测试账号配置。
- D：不需要为本 change 修改代码。

## 验收结果

已注册且可用的普通用户可以用 `RESET_PASSWORD` 验证码重置密码；未注册邮箱的发送响应不暴露账号存在性；并发提交只有一次成功；事务失败不留下半完成数据；成功后旧 Cookie/JWT 失效；PC 和移动端均可完成并安全退出到登录页。
